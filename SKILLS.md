# HIDUP MALAYSIA Skills Index

Skills are short, enforceable instructions that guard the process gates in `playbook.md`. Claude
Code loads them with the Skill tool; Codex invokes them as `$skill-name`. Facts (layout, rules,
commands) live in `CLAUDE.md` / `AGENTS.md` and `docs/contracts/`; skills point to those facts
instead of copying them.

## Where skills live

| Platform | Path | Notes |
| --- | --- | --- |
| Claude Code | `.claude/skills/<name>/SKILL.md` | **Source of truth.** Edit only this copy. |
| Codex | `.codex/skills/<name>/SKILL.md` and `.codex/skills/<name>/agents/openai.yaml` | Generated by `npm run skills:sync`. Never edit by hand. `CLAUDE.md` becomes `AGENTS.md` on lines that do not already mention `AGENTS.md`. |

## Lifecycle skills (the gates)

| Skill | Invoke when | Gate |
| --- | --- | --- |
| `hidup-workflow` | Starting any task, before reading, answering, planning, reviewing, editing or running commands. Mandatory entry point. | 0. Route |
| `change-intake-discovery` | A non-trivial change where current behaviour, owner, contracts or risks are unknown. Read-only. | 1. Discovery |
| `implementation-gate` | Setting up the branch or worktree (Gate 1.5), and immediately before edits (Gate 4). | 1.5 and 4 |
| `change-design-spec` | Discovery is done; write `docs/specs/<slug>.md` and get approval. | 2. Design spec |
| `tdd-plan` | The spec is approved; write `docs/plans/<slug>.md` and get approval. | 3. TDD plan |
| `verification-review` | Implementation is done; fresh evidence before any "done" claim. | 6. Verification |
| `completion-checkpoint` | Verified; the developer picks commit, push, PR, or leave. | 6.5. Completion |
| `handoff-summary` | End of any AI-assisted task. | 7. Handoff |

## Guard skills (used whenever their trigger applies)

| Skill | Trigger | Guards |
| --- | --- | --- |
| `engine-contract-guard` | Anything under `src/engine/`; `GameState`, actions, events, the public engine API | Pure engine, central action resolution, time only via `advanceTime`, seeded determinism, bounded values |
| `save-compat-guard` | `GameState` shape, `src/engine/save.ts`, migrations, storage keys | `SAVE_VERSION` bump, migration plus test, corrupt saves never crash |
| `content-guard` | Anything under `src/data/`; UI copy, humour, real names, politics, payroll and calorie claims | Real-world data honesty, labels, friendly and fair tone, fictional politics |
| `mobile-ui-guard` | `src/components/`, `src/screens/`, `src/App.tsx`, styling | 360px layout, bottom nav, no dead buttons, contrast, confirmations, UI never mutates state |
| `doc-drift` | Docs disagree with code; any change to layout, rules, contracts, status, commands or process | `CLAUDE.md`, `AGENTS.md`, `SKILLS.md`, `playbook.md`, `docs/contracts/` in sync |

## Role agents

Not skills, but used by them: `.claude/agents/hm-scout.md` (read-only discovery),
`hm-implementer.md` (one planned slice, test-first), `hm-reviewer.md` (one diff, no edits). See
`playbook.md` §11.

## Adding or editing a skill

1. Create or edit `.claude/skills/<name>/SKILL.md`. The folder name is the skill name.
2. Frontmatter has exactly two single-line fields:
   ```yaml
   ---
   name: <name>                 # must equal the folder name
   description: Use when ...    # one line; says when to invoke and what it guards
   ---
   ```
   The first sentence of the description becomes the Codex `short_description` (cut at 110 characters).
3. Keep the body short (under about 120 lines): purpose, inputs, steps or checks, red flags or common mistakes. Point to `CLAUDE.md`, `playbook.md` and `docs/contracts/` for facts.
4. Regenerate the Codex twins and check parity:
   ```bash
   npm run skills:sync    # writes .codex/skills/<name>/SKILL.md and agents/openai.yaml, removes orphans
   npm run skills:check   # exits 1 and lists every mismatch if the twins differ
   ```
5. Add the skill to this index and to the skills tables in `CLAUDE.md` and `AGENTS.md` (`doc-drift`).
6. To remove a skill, delete its `.claude/skills/<name>/` folder and run `npm run skills:sync`; the Codex twin is removed as an orphan.

CI (`.github/workflows/ci.yml`) runs `npm run skills:check` on every push to `main` and every pull request.

## How the scripts work

- `scripts/skills-lib.mjs`: shared helpers (frontmatter parsing, the `CLAUDE.md` to `AGENTS.md` rewrite, the `openai.yaml` template). Node built-ins only.
- `scripts/sync-codex-skills.mjs`: regenerates every Codex twin from the Claude copy and deletes Codex skills with no Claude source.
- `scripts/check-skill-parity.mjs`: fails when a twin is missing, extra, or different, when a frontmatter `name` does not match its folder, or when a `description` is missing or does not start with "Use when".
